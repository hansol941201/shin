# POUR 시공사 대상 B2B 홍보영상

16:9 / 1920×1080 / 30fps / 약 1분 41초. 아바타 없음, 화이트+딥네이비, 건설·기술기업 톤.
슬라이드쇼가 아니라 **한 화면 안에서 정보가 하나씩 쌓이는 Build-up / Sequential Reveal / Stagger** 구성입니다.

HeyGen 편집기가 아니라 HTML/CSS로 모션을 구현하고, Playwright로 프레임을 캡처해 ffmpeg으로 인코딩합니다.
타임라인이 결정론적(`window.seek(t)`)이라 몇 번을 렌더해도 결과가 동일합니다.

## 구성

| 파일 | 역할 |
|---|---|
| `film.html` | 무대(1920×1080), 폰트, 디자인 토큰, 공통 스타일 |
| `film.js` | 내레이션 대본 → 큐 타이밍 자동 계산, 전 장면 DOM 생성, `seek(t)` 렌더러 |
| `render.js` | Playwright로 프레임 캡처 → ffmpeg stdin으로 파이프 → MP4 |
| `probe.js` | 지정 시각의 스틸 캡처(검수용) |
| `ASSETS.md` | 이미지 슬롯 목록과 투입 방법 |

## 실행

```bash
npm run setup      # 의존성 설치 + Pretendard 폰트 배치
npm run render     # OUT=파일명.mp4 FPS=30 로 조정 가능
npm run probe -- 21 52 81    # 해당 초의 스틸을 probe/ 에 저장
```

`ffmpeg`은 **libx264가 포함된 빌드**가 필요합니다(Playwright 번들 ffmpeg은 VP8 전용이라 사용 불가).
`FFMPEG=/path/to/ffmpeg`, `CHROME=/path/to/chrome`으로 경로를 지정할 수 있습니다.

## 장면 구성

| 장면 | 내용 | 핵심 연출 |
|---|---|---|
| 1 | 새로운 공법을 찾는 이유 | 아파트 전경 Push-in / 키워드 3개 순차 등장 / 현장 카드 스태거 / 4단계 프로세스 체인 |
| 2 | 260만 세대 경험과 데이터 | **RAPID COUNT-UP** 0→2,600,000 (1.35초, 지정 마일스톤 스텝) + 스케일 스냅 / 현장 사진 모자이크 채움 / 현장진단 4항목 |
| 3 | POUR 지원 체계 (3-1~3-6) | 용인공장 풀블리드 / 자재 Scale-in+Slide-up / 자료 스택 누적 / AI 4스텝 / 공사 전·중·후 3분할 0.5초 간격 / 방사형 8개 연결 → 60 |
| 4 | 협력 프로세스 | 상단 01·02·03 진행 레일 + 체크 / 스텝별 키워드 순차 / 실제 MOU 문서 중앙 대형 |
| 5 + FINAL | 현장에서 이기는 공법 | 선택→적용→수주→실적 강한 순차 등장 / 실적 모자이크 / POUR 로고 2초 이상 홀드 |

## 내레이션 · 자막

- 현재 버전은 **무음 + 하단 자막**입니다.
- 대본은 `film.js`의 `SCRIPT` 배열이 원본입니다. 각 줄의 길이에서 노출 시간을 계산하고(`RATE` = 초당 9.2자),
  모든 모션이 그 큐 시각을 참조하므로 **대본을 고치면 전체 타이밍이 자동으로 따라옵니다.**
- 실제 VO를 넣을 때는 `RATE`를 실제 낭독 속도에 맞춰 조정한 뒤 재렌더하고, 자막 레이어를 끄고 ffmpeg으로 오디오를 먹싱하면 됩니다.

## 이미지

실사 원본만 사용합니다. 파일이 없는 슬롯은 **AI 이미지로 대체하지 않고** 어떤 원본이 필요한지 라벨이 붙은
플레이스홀더로 남습니다. 슬롯 목록과 투입 방법은 `ASSETS.md` 참고.

## v9 — 라이트 리디자인 (film2.html / film2.js)

기존 v8(`film.html` / `film.js`)은 그대로 두고 새 버전으로 분기했다.

```bash
npm run render:v9     # FILM=film2.html 로 렌더
npm run audit:v9      # 안전여백 / 잘림 / 겹침 자동 점검
npm run luma          # 딥블루(어두운 면) 비중 실측
```

딥블루는 **오프닝 · 260만 카운트업 · 사진 기반 섹션(3-1, 3-2, 3-4) · 클라이맥스 · 엔딩**
에만 쓰고 나머지는 오프화이트~쿨그레이 위 딥블루 텍스트로 간다.
`luma.js` 가 실제 프레임 휘도를 재서 비중을 검증한다(목표 35~40%).

AI 실사 이미지는 `AI_IMAGE_PROMPTS.md` 의 슬롯 이름으로 `assets/` 에 넣으면 자동 반영된다.

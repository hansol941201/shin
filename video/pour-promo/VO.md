# 내레이션 (VO) 작업 안내

## 지금 들어간 목소리

`espeak-ng` 한국어 — **오프라인 포먼트 합성기**다. 기계음이 뚜렷하다.
이 환경에서 품질 좋은 한국어 TTS에 닿을 수 없어서(아래 참고) **타이밍 확인용 가이드 보이스**로 넣었다.
최종 납품본에는 성우 녹음이나 상용 TTS로 교체하는 것을 전제로 한다.

차단된 경로: `huggingface.co`(Piper·Kokoro·MeloTTS 음성 모델),
`speech.platform.bing.com`(Edge TTS), `translate.google.com`(gTTS) — 모두 프록시 정책상 403.
설치 가능했던 것은 apt 의 `espeak-ng` 뿐이다.

## 실제 녹음으로 교체하는 법

1. 줄마다 WAV 를 만들어 `vo_src/` 에 넣는다. 파일명은 `narration_timing.csv` 의 `파일명` 열 그대로.
   ```
   vo_src/s1_00.wav   시공사가 새로운 공법을 찾는 이유는 분명합니다.
   vo_src/s1_01.wav   더 나은 현장을 만들고,
   ...
   vo_src/s5_07.wav   POUR가 함께합니다.
   ```
   16bit PCM 이면 샘플레이트·채널은 알아서 맞춘다. 각 파일은 앞뒤 무음 없이 대사만.

2. 트랙을 다시 만들고 영상에 얹는다.
   ```bash
   RATE=6.6 node _dump_cues.js        # 큐 시각 갱신 (영상과 같은 RATE 를 쓴다)
   python3 build_vo.py                # vo_src/ 가 있으면 TTS 대신 그 파일을 쓴다
   ffmpeg -i POUR_홍보영상_v17.mp4 -i narration.wav \
          -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -ar 48000 -ac 2 \
          -movflags +faststart POUR_홍보영상_최종.mp4
   ```
   `build_vo.py` 는 `vo_src/<파일명>` 이 있으면 그것을 우선 쓰고, 없는 줄만 TTS 로 채운다.
   일부만 먼저 녹음해 섞어 들어봐도 된다.

3. 통짜 한 트랙으로 받았다면 위 2번 대신 그 파일을 바로 `-i` 로 넣으면 된다.
   다만 줄 시작점이 `narration.srt` 와 맞아야 한다.

## 낭독 속도 — 중요

무음+자막 버전(v16, 1:46)은 **초당 9.2자(읽는 속도)** 기준으로 짜여 있었다.
한국어 기업 내레이션은 호흡을 포함해 **초당 6자 안팎**이라, v16 타이밍에 목소리를 얹으면
45줄 중 40줄이 8.5자/초를 넘어 계속 쫓기듯 들린다.

그래서 내레이션 버전은 `RATE=6.6` 으로 타임라인 전체를 다시 잡았다 → **2:19**.
자막 문구와 장면 순서는 그대로고, 각 줄에 주어지는 시간만 늘어난다.
모든 모션이 `L(scene,idx)` 를 참조하도록 짜여 있어 이 값 하나로 전체가 따라온다.

| 버전 | 길이 | 실효 낭독 속도 | 용도 |
|---|---|---|---|
| v16 | 1:46 | 8.19자/초 | 무음 + 자막 전용 |
| v17a | 1:46 | 8.19자/초 | v16 에 목소리만 얹음 — 빠름 |
| **v17** | **2:19** | **6.06자/초** | **내레이션 기준** |

다른 길이를 원하면 `RATE` 만 바꿔 다시 렌더한다.
`RATE=7.2` → 2:09 / `RATE=6.2` → 2:27 / `RATE=5.8` → 2:36

## 자막 파일

`narration.srt` — 대사와 시각. 유튜브·플레이어 자막으로 그대로 쓸 수 있고,
성우에게 넘기는 큐시트로도 쓴다.
`narration_timing.csv` — 파일명 / 시작 / 끝 / 길이 / 글자수 / 자당 속도.

## BGM

넣지 않았다. 승인된 음원을 받으면 내레이션 트랙과 함께 믹스한다
(내레이션 대비 BGM -18~-22dB 권장).
